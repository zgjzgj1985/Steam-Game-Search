# 代码审核规范

> **版本**: v1.0.0
> **更新日期**: 2026-05-11
> **目的**: 建立统一的代码审核机制，系统性控制技术债增长

---

## 1. 路径分隔符规范

**强制要求**：所有文件路径必须使用正斜杠 `/`，禁止使用反斜杠 `\`。

| 正确示例 | 错误示例 |
|---------|---------|
| `src/lib/filter-cache.ts` | `src\lib\filter-cache.ts` |
| `src/app/api/games/search/route.ts` | `src\app\api\games\search\route.ts` |

**原因**：Windows 文件系统不区分路径分隔符，但 Next.js 构建工具、Git 和 import 别名解析对路径格式敏感。统一正斜杠确保跨平台一致性。

**检查规则**：
- 文件名中包含 `\` 或 `\\` 的文件必须重命名
- 代码中的 import 路径字符串不得使用反斜杠
- Next.js 的文件路由系统和 `jsconfig.json`/`tsconfig.json` 的路径别名均基于正斜杠

## 2. 类型定义规范

**强制要求**：共享类型必须放在 `src/types/` 目录下，禁止在页面文件或工具模块中重复定义。

### 2.1 类型存放位置

| 类型归属 | 存放位置 | 说明 |
|---------|---------|------|
| 跨模块共享的游戏数据类型 | `src/types/game.ts` | Game、PokemonLikeAnalysis、AnalysisModuleResult 等 |
| 缓存模块专用类型 | `src/lib/filter-cache.ts` | CachedPoolData、PoolStats 等缓存数据结构 |
| 页面组件 Props | 页面文件顶部内联 | 仅限该页面使用、不被其他模块引用的类型 |
| API 响应类型 | 对应 route.ts 顶部 | 仅该接口使用的类型 |

### 2.2 禁止的做法

- ❌ 在 `page.tsx` 中定义 `GameRecord` 接口，然后又在 `filter-cache.ts` 中重复定义
- ❌ 在多个 route.ts 中复制相同的 Response 类型
- ❌ 在组件文件中定义通用业务类型

### 2.3 正确的做法

- ✅ 类型定义一次，通过 `import { xxx } from "@/types/game"` 共享
- ✅ 页面专用组件的类型内联在页面文件顶部
- ✅ API 响应类型在对应 route.ts 顶部定义，用 `export type` 导出

## 3. 注释规范

### 3.1 必需的注释

**模块/文件头部**：每个独立模块文件必须包含 JSDoc 注释，说明文件用途和数据流向。

```typescript
/**
 * 标签配置模块（前端与后端共享）
 *
 * 此文件包含同义词映射和黑名单配置的单一来源定义。
 *
 * 数据流向：
 * 1. manage_tags.py --export-config → scripts/tag-config.json
 * 2. 此文件从 tag-config.json 读取（服务端）或使用内置默认值（客户端）
 * 3. route.ts 和 page.tsx 使用此模块确保前后端一致
 */
```

### 3.2 禁止的注释

- ❌ 与代码逻辑重复的文字描述（如 `// 计数器 +1` → `counter++`）
- ❌ 显而易见的状态说明（如 `// 正在加载` → `const [loading, setLoading] = useState(false)`）
- ❌ 过时的 TODO 而未标注日期和负责人

### 3.3 Prompt 中的注释规则

在 LLM 提示词模板中：

- ❌ 【重要提示】章节不得重复【输出格式】章节中已描述的字数要求
- ✅ 【重要提示】应聚焦于"不要做什么"或"特别要注意的边界情况"

**错误示例**：
```
【输出格式 - 每个描述字段不得少于300字】
...
【重要提示】每个字段描述必须达到规定字数，禁止简短敷衍
```

**正确示例**：
```
【输出格式 - 每个描述字段不得少于300字】
...
【重要提示】
- 描述要具体、可操作，举例说明
- 不要使用泛化的形容词，要基于数据说话
- 避免在JSON外输出任何文字
```

## 4. 过时代码清理

### 4.1 清理时机

当代码中满足以下任一条件时，必须清理：

- 函数/常量标记为"迁移兼容"、"旧版"、"deprecated"，且确认无调用方
- 被 `// TODO` 标记超过 6 个月未处理的
- 功能重构后遗留的旧代码路径

### 4.2 清理前检查

删除任何标记为"迁移兼容"的代码前，必须执行以下检查：

1. **全项目搜索调用方**：`rg "旧函数名"` 确认无引用
2. **检查 git 历史**：确认该代码在当前分支中未被临时使用
3. **检查数据文件**：确认无硬编码的字段名引用该旧代码

### 4.3 清理后记录

- 删除旧函数后，在 CHANGELOG-HISTORY.md 中记录
- 如删除影响较大（如改变了 API 兼容层），需在 PROJECT.md 版本日志中说明

## 5. 歧义规避

### 5.1 变量命名

- ❌ 禁止单字母变量名（循环计数器 `i`、`j`、箭头函数参数除外）
- ❌ 禁止使用意义模糊的缩写（如 `c`、`tmp`、`data1`）
- ✅ 使用清晰表达含义的名称（如 `poolGames`、`cachedResults`、`featureTagFilters`）

### 5.2 池子标识符

- ❌ 禁止使用数字或其他符号替代 A/B/C 池标识
- ✅ 必须使用英文字母 `"A" | "B" | "C"` 类型约束
- ✅ 在 UI 中显示"池"字（如"A池"、"B池"），数据层使用英文字母

### 5.3 布尔值命名

- ❌ 避免 `flag`、`state`、`status` 等泛化命名
- ✅ 使用具体含义：`isLoading`、`isPokemonLike`、`excludeTestVersions`

## 6. 审核检查清单

每次提交代码前，对照以下清单自检：

### 路径检查
- [ ] 无文件路径包含反斜杠 `\`
- [ ] import 语句中的路径使用正斜杠

### 类型检查
- [ ] 无重复的类型定义（搜索同类接口名）
- [ ] 新增的业务类型已加入 `src/types/game.ts`

### 注释检查
- [ ] 模块头部有 JSDoc 注释
- [ ] 无与代码重复的注释
- [ ] LLM prompt 中无冗余字数要求描述

### 过时代码检查
- [ ] 无标记为"迁移兼容"但已无人调用的函数
- [ ] 无超过 6 个月的未处理 TODO

### 命名歧义检查
- [ ] 无单字母变量（除循环计数器）
- [ ] 池子标识符使用英文字母 A/B/C
