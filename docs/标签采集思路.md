## 一、核心目标（第一性原理）

### 1.1 根本目的

**从海量游戏中发现独特、令人着迷的游戏设计**

不是找共性、不是找趋势，而是发现那些让人眼前一亮、印象深刻、独特的创新点。

### 1.2 什么标签真正有价值？

| 类型 | 定义 | 示例 | 发现价值 |
|------|------|------|----------|
| **品类标配** | 每款游戏都有 | RPG、回合制、卡牌 | 无 |
| **机制层** | 某类游戏的共性 | 肉鸽、牌组构建 | 筛选用 |
| **独特亮点** | 单款游戏的招牌 | 形态融合、骰子驱动 | **发现价值** |

**真正有价值的标签必须满足：**
1. **稀有性**：只出现在少数游戏中（1-5款）
2. **吸引力**：看到这个标签就想玩
3. **独特性**：是这款游戏的标志性卖点
4. **可描述**：能让人理解这是什么机制

## 二、标签分类体系

### 2.1 三层标签架构

```
┌─────────────────────────────────────────┐
│  第一层：品类标配（已过滤）              │
│  RPG / JRPG / 回合制 / 卡牌 等          │
├─────────────────────────────────────────┤
│  第二层：机制层（用于筛选）              │
│  肉鸽融合 / 牌组构建 / 形态融合 等      │
├─────────────────────────────────────────┤
│  第三层：独特亮点（用于发现）            │
│  骰子驱动 / 类魂机制 / 契约驯服 等      │
└─────────────────────────────────────────┘
```

### 2.2 各层标签用途

| 层级 | 用途 | 筛选逻辑 |
|------|------|----------|
| 品类标配 | 过滤 | 全部加入黑名单 |
| 机制层 | 分类/筛选 | 按出现频率统计，用于筛选面板 |
| 独特亮点 | **发现** | 按独特程度排序，用于展示卡片 |

## 三、标签质量评估标准

### 3.1 评价维度

| 维度 | 定义 | 权重 |
|------|------|------|
| **独特性** | 只出现在少数游戏中 | 40% |
| **吸引力** | 让人看了想玩 | 30% |
| **可学习性** | 能提取为设计参考 | 20% |
| **描述清晰度** | 一看就懂是什么机制 | 10% |

### 3.2 评分公式

```
创新价值 = 独特性×0.4 + 吸引力×0.3 + 可学习性×0.2 + 清晰度×0.1
```

**独特性评分**（出现次数越少分数越高）：
- 出现1次：100分
- 出现2次：80分
- 出现3次：60分
- 出现4-5次：40分
- 出现6次以上：20分（接近机制层）

### 3.3 展示优先级

```
按创新价值降序展示
  ↓
Top 标签 = 高独特性 + 高吸引力 + 高可学习性
```

## 五、标签生成流程

> **文档状态**：按频率排序、Prompt冲突、开放标签架构等问题已在 v1.11.0-v1.12.0 修复。本章节描述当前系统的标签生成流程。

### 5.1 当前流程

```
1. LLM分析游戏 → 生成 rawMechanics（原始标签）
2. 聚类映射 → 将相似标签归入机制层（保留rawMechanics原始语义）
3. 过滤黑名单 → 移除品类标配
4. **按创新价值排序** → 独特性优先
5. **只展示亮点标签** → 过滤机制层标签
```

## 九、总结

### 核心原则

1. **发现价值 > 共性统计**：找独特亮点，而不是找共同趋势
2. **低频 ≠ 低价值**：恰恰相反，低频标签往往是最独特的
3. **按独特性排序**：让用户第一眼看到的是让人着迷的标签

### 验收标准

- [ ] 卡片上展示的标签都是"令人想玩"的亮点标签
- [ ] 品类标配和机制层标签不会出现在卡片上
- [ ] 独特标签（出现1-5次）排在前面
- [ ] 每个独特标签都能让人理解是什么机制
